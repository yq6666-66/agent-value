
# agent-value

[English](README.md) | 简体中文

agent-value 是一个给个人用的本地桌面工具。它按成本、时间和质量，给你实际在用的（模型，路线）组合打分，三者的权重按你自己的偏好来定。它不是公开排行榜：每个数字都来自你自己的任务，所有数据都只留在你自己的电脑上。

打分规则依据一份成文的规范（v22），规范没写清的地方另有一份决策记录补上。这两份文件都不在本仓库里；本 README 只讲已经实现的部分。

## 状态

Tauri 桌面应用可从源码在本地构建运行；当前不提供安装包。它通过核心库，对本地存储里编程范围的时间窗打分，并展示前沿、资格、推荐，以及真实性来源和权重来源。你可以跑五级自报向导、打开敏感性面板，记录探针同意，并展示此前已记录或回放的探针结果。同意之后可以手动跑一次探针，也可以启用应用内定时重跑；定时默认关闭，启用后要等一个暂定间隔才第一次发送，退出应用即停止。定时开启时，探针面板会显示下次计划时间，并反映月预算停止。打开应用不会发送探针。观察期档位阈值尚未校准；观察期完成前，档位仅供参考，并标「真实性未定」。探针运行库可以通过 HTTP 采集官方直连指纹基线并写入本地存储；测试使用模拟服务器，观察期阈值不变。桌面应用把数据存在本机。你可以列出和添加臂、查看数据库路径、导出和清空全部记录；时间窗结果视图展示可调整宽度的前沿，旁边是权重面板；首个窗口显示首窗提示，不显示 V。

## 基本概念

1. **打分范围。** 每类任务单独打分。默认有两个范围：编程和非编程。不同范围的分数从不合并。
2. **臂（arm）。** 被比较的单位：一个模型加一条路线。路线包括 API 主机、协议（例如 Anthropic Messages 或 OpenAI Chat Completions）和所用的 agent 或客户端。三者中任何一项不同，就是另一条臂。同一条路线上换 API key 不算新臂。
3. **单元和层。** 任务按子类分进单元 $u$ （编程默认分为：修复、新增、重构、解释与审查、其他）。默认只有一层；也可以按任务规模（小、中、大）把任务分成层 $d$，规模只按你自己的输入来量，这时一个单元就是某层里的一个子类。每个单元有一个权重 $\omega_u$，等于上一窗里该单元在本层任务中所占的份额。
4. **任务。** 从你提交到交付、放弃或取消为止的一段过程。
5. **时间窗。** 打分以 30 天为一窗。每窗开始时，单元权重、你的权重版本、价目表和分类规则都按之前的数据冻结；参照臂和兜底臂选定以后也同样冻结（选取规则见下一条）。第一窗不给出 $V$，库里已经实现了这一点。按规范，第一窗仍要展示各臂的成本、时间、质量和前沿，并标明“尚未校准”。桌面已展示带“尚未校准”标注的第一窗前沿；$V$ 仍不给出。
6. **参照臂 $R_k$ 和兜底臂 $F_k$。** $R_k$ 是所有其他臂都要拿来比较的那条臂。一条臂失败 $K$ 次后，任务交给 $F_k$。参照臂和兜底臂自身不再往下交给别的臂。 $R_k$ 按以下顺序取第一条可用的臂：你指定的臂；该评分范围内的官方直连臂；上一窗任务数最多的臂。可用是指这条臂在上一窗通过了真实性门槛，并且没有 $F_{\rm bad}$ 单元；任务数相同时取 id 排在前面的臂。有多条官方直连臂时按上一窗任务数从多到少逐条检查；任务数最多的那条不可用就用下一条官方直连臂，只有所有官方直连臂都不可用时才取上一窗任务数最多的臂。默认 $F_k=R_k$。你也可以另选 $F_k$，但只有它在上一窗通过真实性门槛、没有 $F_{\rm bad}$ 单元、在每个正权重层都是 I 档或 II 档（见第 5 节），并且每个正权重单元都至少有 3 条评分（ $n_q\ge3$）时才保留。否则 $F_k$ 退回 $R_k$，它连一个正权重层都没有时也一样；版本记录里会写明这次回退和原因。

## 打分原理

记号： $i$ 表示臂， $u$ 表示单元， $d$ 表示层。含义清楚时省略下标；除非另有说明，每个量都按“每条臂、每个单元”计算。 $\mathrm{NA}$ 表示“无定义”，代码从不把它当成 0。

### 1. 任务结果和质量信号

*规范 §3.1。已实现。*

每个任务只得到一个结果。规则从上往下检查，第一条成立的规则说了算：

1. 你明确中止了任务：**取消**。
2. 任务运行过检查（测试、构建、类型检查），且最后一次检查失败：**失败**。
3. 任务结束后 30 分钟内，你在同一会话或同一工作目录里发了一条消息，冻结的分类器判定为返工或纠正：**失败**。提新功能不算返工。
4. 编程任务的改动在 24 小时内被全部回滚：结果事后**改判为失败**。
5. agent 报告完成，最后一次检查（如果有）通过，且第 3、4 条都没触发：**成功**。
6. 其他情况（日志不完整、没有完成信号、会话中断）：**未定**。未定永远不算成功。

30 分钟的返工窗口结束前，结果都只是暂定；编程任务还要等 24 小时的回滚窗口结束。由这些结果得到每个单元的计数： $n^1$ （成功）、 $n^0$ （失败）、 $n^C$ （取消）和 $m$ （未定）。

质量 $q_j\in[0,1]$ 只在成功的任务上量，而且只来自你的评分：1-5 星对应 $q_j=(s-1)/4$。为了避免只有出了问题的任务才被打分，核心库会从成功的任务里随机挑 10% 发起评分请求，每天最多 3 次（按北京时间）；真正向你发出评分请求的界面还在计划中。改动保留了多少从不当作质量，因为那样会奖励小改动、惩罚合理的重构；它只用作诊断。

每一层每一窗采用以下两种质量模式之一：

1. **评分模式**：调用方传入的候选名单里（这份名单应当就是第 6 节的资格集合 $\mathcal E_d$，但库里还没把两者接起来），每条臂在每个正权重单元里都至少有 3 条评分。参照臂或兜底臂只有本身是候选时才计入。评分会向一个合并均值 $q_B$ 收缩（上一窗该单元所有臂的均值，没有就取 $0.5$）：

$$
\hat q=\mathrm{clip}\!\left(\frac{\sum_{j=1}^{n_q}q_j+m_0q_B}{n_q+m_0},\ 0.01,\ 0.99\right),\qquad m_0=0.5 .
$$

2. **成功率模式**：其他情况。本层每条臂，包括参照臂，都取 $\hat q=0.99$，于是 $Q^{\ast}$ 就变成成功交付的概率。结果会照此标注（和展示功能一起实现，计划中），而不是把缺数据当成平均质量来展示。

### 2. 单元权重和单元状态

*规范 §0。已实现。*

**单元权重。** 对第 $t$ 窗， $\omega_u$ 等于第 $t-1$ 窗里你在单元 $u$ 的任务数，除以你在整层的任务数。按任务数算，不按成本或时间，探针任务不计入。如果该层上一窗没有任务，就沿用上一份有效权重；如果也没有，就给配置好的各子类平均分配权重。下文所有计数和打分都只用 $\omega_u>0$ 的单元。设计里预留了一个单独的探针单元，权重恒为 0（探针见第 11 节）。

**单元状态。** 每条臂的每个正权重单元，都恰好处于一种状态：

$$
\mathrm{miss}:\quad n^1+n^0=0,
$$

$$
\mathrm{fail}:\quad n^1+n^0>0\ \wedge\ \bigl(n^1+n^0<3\ \vee\ p_K^{lo}<0.75\ \vee\ p_K^{C,lo}<0.75\bigr),
$$

其余情况为 $\mathrm{valid}$ （有效）。处于 fail 状态的单元分两种，按以下顺序判断：

1. $F_{\rm thin}$ （样本太少）： $n^1+n^0<3$。这时不检查悲观通过率，因为样本这么少时它不可靠。
2. $F_{\rm bad}$ （确实失败）： $n^1+n^0\ge3$，且 $p_K^{lo}<0.75$ 或 $p_K^{C,lo}<0.75$。

$p_K^{lo}$ 和 $p_K^{C,lo}$ 在下一节定义。代码还会按层统计各状态的单元数，并把它们的权重加总；参照臂用的是完全相同的规则。在 $\mathrm{miss}$ 单元里， $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$ 及其抗取消版本都是 $\mathrm{NA}$。

### 3. 通过率和重试

*规范 §1。已实现。*

对每条臂的每个单元，这些量给出该臂在自己的 $K$ 次尝试内完成任务的概率，以及途中预计会失败几次。

**先验。** 每个单元从一个基础通过率 $p_B$ 出发：有直接基准就用直接基准，没有就用同层均值，再没有就取 $0.5$。先验强度 $\kappa$ 决定 $p_B$ 相对于你自己的结果占多大分量：

$$
\kappa=
\begin{cases}
n_B, & \text{direct pooling } (\rho=1),\\[2pt]
\dfrac{\kappa_p\,n_B}{\kappa_p+n_B}, & \text{discounted } (0\le\rho<1),\\[6pt]
\min(\kappa_p,3), & \text{same-layer mean used for } p_B,\\
0, & \text{no benchmark and no layer mean (Jeffreys)},
\end{cases}
\qquad \kappa_p=20\rho .
$$

$n_B$ 是基准的样本量， $\rho$ 表示基准和你自己的任务有多接近。 $\kappa$ 在 $\rho=1$ 处有跳变；这是照规范写的，已列为待定问题。

**后验首次通过率。**

$$
\alpha=\kappa p_B+n^1+0.5,\qquad
\beta=\kappa(1-p_B)+n^0+0.5,\qquad
p_1=\frac{\alpha}{\alpha+\beta}.
$$

$+0.5$ 是 Jeffreys 半计数，所以完全没有先验（ $\kappa=0$）时，臂从 $\mathrm{Beta}(0.5,0.5)$ 出发。取消和未定的任务不计入 $\alpha$ 或 $\beta$。

**重试。** 一条臂自己最多尝试 $K=3$ 次。失败以后，每多试一次，成功的概率是 $\pi$。目前 $\pi$ 由调用方传入；从你的数据中估计它还在计划中。如果 $K$ 次全部失败，任务交给兜底臂 $F_k$，它最多再试 $K$ 次，所以每个任务最坏要试 $2K=6$ 次。

$$
q_K=(1-p_1)(1-\pi)^{K-1},\qquad p_K=1-q_K,
$$

$$
E[n_F]=(1-p_1)\sum_{j=0}^{K-1}(1-\pi)^{j},\qquad
E[n_W]=E[n_F]-q_K .
$$

| 符号 | 含义 |
|---|---|
| $p_K$ | 该臂在自己的 $K$ 次尝试内成功的概率 |
| $q_K$ | 该臂自己的 $K$ 次尝试全部失败、任务被转交的概率 |
| $E[n_F]$ | 该臂自己失败次数的期望 |
| $E[n_W]$ | 重试前等待次数的期望。前 $K-1$ 次里每失败一次，后面都会再试一次，不管那次结果如何。第 $K$ 次失败直接转给兜底臂，没有等待，所以不计入。 |

这四个量都只描述该臂自己的尝试，不含兜底臂内部的重试。兜底臂的成本、时间和质量，在第 4 节里通过 $q_K$ 项按每个任务计入一次。

**悲观通过率和抗取消版本。** 单元状态判定用的是 $p_1^{5\%}=\mathrm{Beta}^{-1}(0.05;\alpha,\beta)$ 和 $p_K^{lo}=1-(1-p_1^{5\%})(1-\pi)^{K-1}$。抗取消版本把取消算作失败，即 $\tilde n^0=n^0+n^C$，再用同样的公式重新算 $p_1^C$、 $p_K^C$、 $q_K^C$、 $E^C[n_F]$、 $E^C[n_W]$ 和 $p_K^{C,lo}$。

<details>
<summary>实现说明</summary>

1. 先算 $q_K$，再令 $p_K=1-q_K$，这样 $p_K+q_K=1$ 严格成立。 $E[n_F]$ 逐项求和，不用闭式 $(1-p_1)\frac{1-(1-\pi)^K}{\pi}$；这样 $\pi$ 极小时不会出现相消误差， $\pi=0$ 时也不用特殊处理，此时结果就是 $K(1-p_1)$。
2. 不合格判定不对 Beta 分布求逆。它先算 $x^{\ast}=1-0.25/(1-\pi)^{K-1}$；若 $x^{\ast}\le0$ 则单元通过，否则当 $\mathrm{BetaCDF}(x^{\ast};\alpha,\beta)>0.05$ 时判为不合格。这与 $p_K^{lo}<0.75$ 等价。分位数用对 CDF 二分的方法求出，只用于展示。不完全 Beta 函数在本 crate 里自己实现。
3. 先验用一个显式的枚举来选（`DirectPool`、`Discounted(ρ)` 且 $\rho\in[0,1)$、`LayerMean`、`Jeffreys`），而不是拿 $\rho$ 和 1 比大小。`Discounted` 在 $\kappa_p+n_B=0$ 时给出 $\kappa=0$；`Discounted(1.0)` 和 $\rho<0$ 都返回错误。

</details>

### 4. 单元的成本、时间和质量： $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$

*规范 §2-§3。已实现。*

把一个单元里的一个任务交给某条臂，算上重试、取消和转交，这三个量分别是期望成本、期望活跃时间和期望交付质量。

**输入。** 一个任务的成本 $c$，有实际扣费时就用它所有请求的实际扣费（中转站余额变化或账单明细，按调用 ID 去重），没有就用 token 用量（输入、输出、缓存读、缓存写，含中转站倍率）乘以冻结的价目表，再没有就是 $\mathrm{NA}$。库接收的成本已经折算成人民币；下面几条是给负责汇总成本的一方定的输入约定（汇总本身还在计划中）。订阅制路线按该任务占当月 token 的份额分摊月费；赠送额度按价目表计价，不算 0；分类器和判分模型的费用不计入。时间 $t$ 指活跃时间：挂钟时间减去等你的时段（权限确认、向你提问）。等待时长和打断次数会作为诊断信息和 $T^{\ast}$ 并排展示（和展示功能一起实现，计划中）。

**两侧均值。** 对每一侧（成功任务、失败任务），记 $m_S$ 或 $m_F$ 为这一侧取值不是 $\mathrm{NA}$ 的任务数，所以 $m_S\le n^1$， $m_F\le n^0$。用 $m^{\prime}$ 统称这两个数。均值先做缩尾： $m^{\prime}\ge10$ 时，把最大的 $k(m^{\prime})=\max(1,\lfloor0.01m^{\prime}\rfloor)$ 个值和最小的 $k$ 个值，分别替换成剩余值中离它们最近的值； $m^{\prime}<10$ 时直接用原始均值，并标明未缩尾。然后再向基准收缩：

$$
\tilde C_S=\frac{m_S\bar C_S^w+\kappa_C C_S^B}{m_S+\kappa_C},\qquad
\tilde C_F=\frac{m_F\bar C_F^w+\kappa_C C_F^B}{m_F+\kappa_C},\qquad
\kappa_C=5 .
$$

时间用同样的公式。没有基准时不做收缩， $\tilde C=\bar C^w$。如果某一侧没有样本，它的值依次退回直接基准、该臂在本层的合并均值，最后是 $\mathrm{NA}$。

**成本。**

$$
C^*_{iu}=p_{K}\tilde C_{S}+E[n_F]\tilde C_{F}
+q_{K}\,C^*_{F,u}
+\frac{n^C\hat{\bar C}_{C}}{n^1+n^0} .
$$

从左往右依次是：成功那次尝试的成本、失败尝试的成本、转交给兜底臂的成本，以及把取消任务的成本摊到已完成任务上的部分。 $\hat{\bar C}_C$ 是一个取消任务的平均成本；没有取消账单时，依次退回 $\max(\tilde C_F,\ \text{layer pool})$ （layer pool 即本层合并值）、 $\max(\tilde C_F,\ C_F^B)$，最后是 $\mathrm{NA}$。参照臂和兜底臂自身的转交项为 0，因为它们是最后一站。

**时间。**

$$
T^*_{iu}=p_{K}\tilde T_{S}+E[n_F]\tilde T_{F}
+E[n_W]D+q_{K}T^*_{F,u}
+\frac{n^C\bar T_{C}}{n^1+n^0} .
$$

$D$ 是一次失败到下一次重试之间的间隔。缺这个值时先用本层的合并值，再用基准；两者都没有时，时间不可比，也不出总分。

**质量。**

$$
Q^*_{iu}=p_{K}\hat q+q_{K}\bar Q_{F},\qquad
\bar Q_{F}=\frac{f\,Q^{\rm match}+\kappa_F Q^*_{F,u}}{f+\kappa_F},\qquad \kappa_F=5 .
$$

$\bar Q_F$ 是该臂失败后由兜底臂完成任务时得到的质量：在 $f$ 个配对样本上观察到的质量，向兜底臂自己在该单元的质量收缩。参照臂和兜底臂自身的转交项为 0： $Q^{\ast}_{R,u}=p_K\hat q$。

**缺失的数据不补。** 如果参照臂在某个单元的某一维因任何原因是 $\mathrm{NA}$，那么所有臂在该单元的这一维都是 $\mathrm{NA}$。当 $F_k\ne R_k$，且兜底臂有任何一维是 $\mathrm{NA}$ 时，候选臂在该单元的三维全部是 $\mathrm{NA}$。不存在另一个去掉转交项的“裸”成本。

**抗取消版本。** 这里把 $p_K$、 $q_K$、 $E[n_F]$ 换成抗取消的值，并把取消项换成取消任务超出一次正常失败的那部分额外成本：

$$
C^{*,C}_{iu}=p^C_{K}\tilde C_S+E^C[n_F]\tilde C_F+q^C_K C^*_{F,u}
+\frac{E_{C}}{n^1+n^0},
$$

$$
E_{C}=
\begin{cases}
\displaystyle\sum_{j\in\mathcal C}\max\bigl(0,\ c_j-\tilde C_{F}\bigr), & \text{per-task bills},\\[8pt]
E^{UB}_{C}, & \text{aggregate bill with a per-task cap},\\[4pt]
E^{LB}_{C}, & \text{aggregate bill with no cap, or no cancel bills},
\end{cases}
$$

$$
E^{LB}_{C}=n^C\max\bigl(0,\bar C_{C}-\tilde C_{F}\bigr),
$$

$$
E^{UB}_{C}
=\left\lfloor\frac{S_{C}}{U}\right\rfloor\max\bigl(0,\ U-\tilde C_{F}\bigr)
+\max\!\left(0,\ S_{C}-\left\lfloor\frac{S_{C}}{U}\right\rfloor U-\tilde C_{F}\right),
\qquad S_{C}=n^C\bar C_{C}.
$$

$U$ 是单个任务的扣费上限， $S_C$ 是取消任务的账单总额。 $E^{UB}$ 是在已知总额和上限的情况下额外成本可能的最大值； $E^{LB}$ 是下界。只有下界可用时，该单元会被标记，并关闭抗取消比较。时间用同样的公式。最后用一道单调性保护，保证抗取消版本永远不会比普通版本更好：

$$
C^{*,C}\leftarrow\max(C^{*,C},C^*),\qquad
T^{*,C}\leftarrow\max(T^{*,C},T^*),\qquad
Q^{*,C}\leftarrow\min(Q^{*,C},Q^*),
$$

其中 $Q^{\ast,C}_{iu}=p^C_K\hat q+q^C_K\bar Q_F$。

<details>
<summary>实现说明</summary>

1. 规范把 $E^{UB}$ 的第一项写成 $\lfloor S_C/U\rfloor(U-\tilde C_F)$，当 $U<\tilde C_F$ 时它会变成负数。代码对这一项取了 $\max(0,\cdot)$。当 $U\ge\tilde C_F$ 时两者一致。在 $S_C$ 恰好是 $U$ 的整数倍处，表达式是连续的，所以 $\lfloor S_C/U\rfloor$ 不加容差。
2. $E^{UB}$ 只在 $0\le S_C\le n^CU$ 时有定义。超出这个范围时，单元计算返回错误，不返回数字； $S_C=n^CU$ 是允许的。 $n^C=0$ 时账单必须为空；如果给了上限，上限必须为正。
3. 成本或时间为 $\mathrm{NA}$ 的任务不进入该维的样本； $p_K$ 仍用完整的 $n^1$ 和 $n^0$。“本层合并值”指该臂在本层所有正权重单元的原始样本合在一起做缩尾。库从调用方接收这个合并均值；从本地数据库里算出它还在计划中。取消时间 $\bar T_C$ 的退回顺序和成本相同。
4. 如果 $f>0$ 但缺 $Q^{\rm match}$，质量为 $\mathrm{NA}$；如果 $f=0$，则 $\bar Q_F=Q^{\ast}_{F,u}$。
5. 溢出或出现 NaN 时返回错误。任何一维是 $\mathrm{NA}$ 时，抗取消比较的标记都是关闭的。

</details>

### 5. 聚合和价值分 $V$

*规范 §4、§7。已实现。*

先用单元权重对单元值求加权平均，再用层权重对层值求加权平均：

$$
C^*_{i,d}=\sum_{u\in d^+}\omega_uC^*_{i,u},\qquad
C^*_i=\sum_{d\in D^+}\omega_dC^*_{i,d},
$$

$T^{\ast}$ 和 $Q^{\ast}$ 同理。 $d^+$ 和 $D^+$ 是权重为正的单元和层。只要有一个正权重单元是 $\mathrm{NA}$，聚合结果就是 $\mathrm{NA}$；剩下的单元不会重新分配权重。

价值分把一条臂和参照锚点在三维上同时比较：

$$
V_{i,d}=100
\left(\frac{C^{\rm ref}_{R,d}+c_0}{C^*_{i,d}+c_0}\right)^{a}
\left(\frac{T^{\rm ref}_{R,d}+t_0}{T^*_{i,d}+t_0}\right)^{b}
\left(\frac{1-Q^{\rm ref}_{R,d}+\epsilon}{1-Q^*_{i,d}+\epsilon}\right)^{g}.
$$

1. $V=100$ 表示整体和参照一样好。高于 100 更好，低于 100 更差。
2. 每个因子都是“参照比本臂”的比值，所以成本更低、时间更短、缺陷（ $1-Q^{\ast}$）更少，都会让 $V$ 变大。
3. $a$、 $b$、 $g$ 是你给成本、时间和质量的权重，来自当前的权重版本。三者之和为 1，每个至少 $0.05$；没有任何依据时各取 $1/3$。
4. $c_0=0.15$ 元、 $t_0=15$ 秒和 $\epsilon=0.02$ 是底噪。它们防止极便宜、极快或接近完美的臂之间的微小差别被放大成巨大的比值。
5. $(C^{\rm ref},T^{\rm ref},Q^{\rm ref})$ 是参照锚点。库按层认证这个锚点，见下文。

总体 $V_i$ 用同一个公式，代入总体值即可。单元级的 $V_{iu}$ 只用于诊断。 $V$ 在对数空间里计算，要求 $c_0,t_0,\epsilon>0$、 $C,T\ge0$、 $Q\in[0,1]$。

**参照锚点。** 参照臂的单元和其他臂一样，判定 $\mathrm{miss}$、 $\mathrm{fail}$、 $\mathrm{valid}$ 三种状态，并区分 $F_{\rm thin}$ 和 $F_{\rm bad}$。然后每一层归入一档，按 III、II、I 的顺序判定，先命中的为准。

1. **III 档，不认证。** 参照臂有 $\mathrm{miss}$ 单元、有 $F_{\rm bad}$ 单元、有某个正权重单元的某一维是 $\mathrm{NA}$，或者 $\mathrm{valid}$ 单元不到 3 个。命中的原因全部列出，按这个顺序。这一层不出 $V_{i,d}$，但各臂的 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$ 和第 8 节的官方前沿照常给出。因为先判 III 档，正权重单元不到 3 个的层永远不会被认证，即使每个单元都有效。
2. **II 档，夹逼。** 不是 III 档，并且参照臂至少有一个 $F_{\rm thin}$ 单元。夹逼的是层锚点，单元值不动：

$$
X^{\rm anchor}_{R,d}={\rm clip}\bigl(A_X,\ (1-\theta)a_X,\ (1+\theta)a_X\bigr),\qquad
A_X=\sum_{u\in d^+}\omega_uX^*_{R,u},\qquad
a_X=\frac{\sum_{u\in{\rm valid}}\omega_uX^*_{R,u}}{\sum_{u\in{\rm valid}}\omega_u},\qquad
\theta=0.10 .
$$

$X$ 代表成本和时间。质量通过缺陷 $D=1-Q$ 夹逼， $A_D$ 和 $a_D$ 在 $D$ 上同样定义： $Q_{R,d}^{\rm anchor}=1-{\rm clip}\bigl(A_D,(1-\theta)a_D,(1+\theta)a_D\bigr)$。层值落在窗口内就原样使用，只有越界的才拉回边界。单元值一律不变，所以第 4 节的兜底项仍用实测值。库会保留 $A$、 $a$、夹逼后的值和参照臂 $F_{\rm thin}$ 单元的权重，供表头使用。II 档下纯路由臂（每个单元都和参照臂相同的臂）不一定是 100 分，图例里必须写明这一点。

3. **I 档，全认证。** 其余情况。锚点取参照臂的实测层值，纯路由臂恰好 100 分。

$V$ 从不除以纯路由臂的分数来把它拉回 100；那样会把夹逼抵消掉，II 档就白做了。

### 6. 资格门槛 $\mathcal E_d$

*规范 §5。已实现。真实性和日志完整性的输入来自第 11 节。*

一条臂要通过全部五道门槛，才能进入某一层的主比较，也就是集合 $\mathcal E_d$：

1. **完整样本。** 该臂在本层没有 $\mathrm{miss}$ 单元，也没有 $\mathrm{fail}$ 单元： $N_{i,d}^{\rm miss}=0$ 且 $N_{i,d}^{\rm fail}=0$。
2. **样本量。** $U_d$ 是本层正权重单元的个数：

$$
n^{\rm comp}_{i,d}=\sum_{u\in d^+}\bigl(n^1_{iu}+n^0_{iu}\bigr)\ge\max(30,\,3U_d).
$$

3. **取消率和完成率。** $N^{\rm sub}_{i,d}$ 是本层提交给该臂的任务数：

$$
\frac{n^C_{i,d}}{N^{\rm sub}_{i,d}}\le0.20,\qquad
\frac{n^1_{i,d}+n^0_{i,d}}{N^{\rm sub}_{i,d}}\ge0.50 .
$$

4. **真实性和日志完整性。** 看第 11 节的真实性档位：官方直连、A、A− 通过，C 不通过；开启探针时 B 不通过，关闭探针时 B 通过，并标上“未验证（探针已关闭）”。观察期校验通过之前，所有判了档的臂都通过，并标上“真实性未定”。第 11 节的日志完整性检查必须通过。
5. **参照底座。** 在本层每个正权重单元里，参照臂的 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$ 都有定义（不是 $\mathrm{NA}$）。参照臂没有 $\mathrm{miss}$ 单元是必要条件，但不够，因为有样本的单元也可能最后算出 $\mathrm{NA}$。

结果会给出该臂是否合格、没通过的每一道门槛，以及“真实性未定”标记。

<details>
<summary>实现说明</summary>

1. 两道比率门槛用整数比较： $5n^C\le N^{\rm sub}$ 和 $2n^{\rm comp}\ge N^{\rm sub}$，所以边界上没有舍入问题。 $N^{\rm sub}=0$ 时两道比率门槛都不通过，也不做除法。
2. 五道门槛每次都全部检查，没通过的全部列出，按固定顺序、不重复；不会在第一道失败时就停下。
3. $n^C$ 和 $N^{\rm sub}$ 只在有数据的正权重单元上累加， $\mathrm{miss}$ 单元计 0。所以在含 $\mathrm{miss}$ 单元的层里，失败列表可能同时列出某道比率门槛。不管怎样，这条臂都会因为完整样本门槛而不合格。
4. 参照底座门槛从调用方接收参照臂的三元组，不检查它们是不是真的由参照臂算出。同一个单元传两次会返回错误。
5. 归因时，每个失败标签都对回五道门槛中的一道；完整样本门槛已经没过时，主要失败原因里不再列两道比率门槛（第 9 步）。
6. 第 9 步已经用规范里的例 6 对照过这些门槛。

### 7. 诊断表

*规范 §5。已实现为库函数；表格本身还没有展示出来。*

某一层里有 $\mathrm{miss}$ 或 $\mathrm{fail}$ 单元的臂不在 $\mathcal E_d$ 里。诊断表给这样的臂单独算一个带标注的估计，永远不和主结果混在一起。

**准入。** 臂至少要有一个 $\mathrm{valid}$ 单元，并且满足下式，才给诊断分：

$$
{\rm ESS}_{i,d}=n^{\rm comp}_{i,d}+\kappa_{\rm eff}\ge3 .
$$

这里的 $\kappa_{\rm eff}$ 是第 3 节的先验强度 $\kappa_{iu}$ 按 $\omega_u$ 在本层全部正权重单元上加权平均的结果。先验由调用方传入；没传先验的单元按 $\kappa=0$ 计，权重仍算在分母里。用 Jeffreys 先验时 $\kappa=0$， $\mathrm{ESS}$ 就等于 $n^{\rm comp}$。

**填补空缺。** 填补值只用该臂本层 $\mathrm{valid}$ 单元的普通 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$，不用取消稳健版本。

1. $\mathrm{miss}$ 单元有两个值。乐观值是各有效单元的加权中位数，成本、时间、质量分别取。取的是下中位数：先把有效单元的权重归一化，再把值排好序，累计权重第一个达到一半的那个值胜出。质量按缺陷 $1-Q$ 排序，所以平局时总是取更好的那个真实单元。保守值是每个维度上最差的有效值：最高的成本、最高的时间、最低的质量，三者可以来自不同单元。
2. $\mathrm{fail}$ 单元只有一个值：每个维度上，取它的实测值和最差有效值中更差的那个。

填补后的单元按第 5 节在本层聚合两次：一次所有 $\mathrm{miss}$ 单元都取乐观值，一次都取保守值； $\mathrm{fail}$ 单元两次都用它唯一的那个值。有 $\mathrm{miss}$ 单元的臂以区间 $[V^{\rm diag,cons},V^{\rm diag,opt}]$ 展示；只有 $\mathrm{fail}$ 单元的臂得到单个 $V^{\rm diag}$，并标出不合格单元的总权重 $w^{\rm fail}_{i,d}$。 $V$ 用诊断参照锚点来算，它不看分档，也从不夹逼。锚点按规范第 570 行逐维度取最差有效值：在参照臂所有正权重的 $\mathrm{valid}$ 单元里，成本和时间各取最高值，质量取最低值，三维分开取，可以来自不同单元。有效单元某一维为 $\mathrm{NA}$ 时，其余维度仍计入。然后在每个正权重单元上，参照臂每一维取自身值和这个最差有效值里更差的那个；某一维为 $\mathrm{NA}$ 就直接取最差有效值。这个锚点由库函数算出，再由调用方传给这一行。某一维在参照臂所有正权重有效单元里都缺失时就没有锚点，这一行也就没有 $V$。

**排序。** 各行按有效单元覆盖率从高到低排，相同时按模型名排：

$$
{\rm cov}_{i,d}:=1-w^{\rm miss}_{i,d}-w^{\rm fail}_{i,d}
$$

不提供按诊断 $V$ 排序的入口。

<details>
<summary>实现说明</summary>

1. 诊断行里的层聚合值是填补以后算的。像规范例 8 里的 $A_C=0.165$ 这种原始实测层均值，要由调用方用实测值另算，库里不存。
2. 臂没有准入时，这一行会列出所有命中的原因： $\mathrm{ESS}<3$ （`EssBelowThree`）；没有 $\mathrm{valid}$ 单元（`NoValidCell`）；某个有效单元的 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$ 不完整，没法算填补值（`ValidCellIncomplete`）。列表为空当且仅当这一行准入。
3. 坏输入返回错误：同一个单元传了两次，权重或 $\kappa$ 不是有限数，或者 $\mathrm{fail}$ 单元缺完整的实测三元组。
4. 已经和规范例题对照过：例 6 的 $F_{\rm thin}$ 单元和诊断聚合值 0.7875，例 7 的 $F_{\rm bad}$ 单元和 0.9000。例 8 的原始均值 0.1650 由第 6、7 步的测试对照。

</details>

### 8. 前沿

*规范 §6。核心已实现；桌面展示编程范围时间窗结果（前沿、资格、推荐、真实性/权重来源）。外壳读存储并请求核心；网页视图不重算。*

在某一层的合格臂里，如果臂 $j$ 在每个维度上都不比臂 $i$ 差（成本、时间不更高，质量不更低），并且至少有一个维度严格更好，就说 $j$ 支配 $i$。权重 $a$、 $b$、 $g$ 在这里不起作用。

$$
\mathcal F^{\rm off}_d=\{i\in\mathcal E_d:\nexists j\in\mathcal E_d,\ j\succ_{\rm off}i\},\qquad
\mathcal F^{\rm rob}_d=\{i\in\mathcal E_d:\nexists j\in\mathcal E_d,\ j\succ_{\rm rob}i\}
$$

$$
\mathcal F^{\rm rec}_d=\{i\in\mathcal F^{\rm off}_d:\nexists j\in\mathcal E_d,\ j\succ_{\rm rob}i\}
$$

$\succ_{\rm off}$ 比较普通的 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$， $\succ_{\rm rob}$ 比较取消稳健版本。 $\mathcal F^{\rm off}_d$ 是官方前沿， $\mathcal F^{\rm rob}_d$ 是取消稳健前沿， $\mathcal F^{\rm rec}_d$ 是推荐集：官方前沿上那些在取消稳健值上没有被任何臂胜过的臂。

**每层的官方推荐。** 在 I 档或 II 档的层里，官方第一是 $V_{i,d}$ 并列最高的所有臂，只在 $\mathcal F^{\rm rec}_d$ 里选。III 档的层照样有前沿，但没有第一。 $\mathcal F^{\rm rec}_d$ 为空时没有第一： $\mathcal F^{\rm rob}_d$ 单独列为“取消稳健备选”，从不标成官方第一。

**账单过粗。** 如果一条臂有某个正权重单元的取消账单只给出下界（见第 4 节），这条臂在这一层的取消稳健支配就被禁用，并标上“账单过粗”。这一层里凡是显示这条臂的行都带这个标记，不管它在不在 $\mathcal F^{\rm rec}_d$ 里。带标记的臂仍然可以当官方第一，标记照样保留。

**总体。** 一条臂所有正权重层的值都有定义时，就算出并给出它的总体 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$，同时给出有效覆盖率：

$$
{\rm cov}_i=\sum_{d\in D^+}\omega_d\bigl(1-w^{\rm miss}_{i,d}-w^{\rm fail}_{i,d}\bigr).
$$

${\rm cov}_i<1$ 的臂标为非全覆盖，只用于诊断，不进前沿、不进推荐、不参与排序。总体参照锚点是各层锚点按层权重相加：

$$
X^{\rm ref}_R=\sum_{d\in D^+}\omega_dX^{\rm anchor}_{R,d},\qquad X\in\{C,T,Q\}.
$$

只要有一个正权重层是 III 档，总体参照就记为 $\mathrm{NA}$：不出总体 $V$，也不出总体推荐，只给出各臂的总体值和各层自己的前沿，表头注明部分层的参照未认证。这时只显示这一条表头；总体参照已认证、并且有正权重层是 II 档时，表头才注明参照含 II 档夹逼层。一条臂要得到总体 $V_i$，总体参照必须已认证，而且这条臂要通过整个网格上的全部门槛： $n_i^{\rm comp}\ge\max(30,3U_i)$，没有 $\mathrm{miss}$ 或 $\mathrm{fail}$ 单元，取消不超过 20%，完成不低于 50%，真实性通过，并且至少在一个正权重层的官方前沿上（ $i\in\mathcal F^{\rm all}$）。总体第一是总体 $V_i$ 并列最高的所有臂。

<details>
<summary>实现说明</summary>

1. 调用方传入 $\mathcal E_d$ 里的臂；前沿函数自己不检查资格。
2. 普通三元组里有 $\mathrm{NA}$ 的臂不进 $\mathcal F^{\rm off}_d$；取消稳健三元组里有 $\mathrm{NA}$ 的臂不进 $\mathcal F^{\rm rob}_d$，也不参加任何取消稳健比较。
3. 取消稳健值只在普通值为 $\mathrm{NA}$ 的地方才是 $\mathrm{NA}$，所以用库自己算出的值，官方前沿上的臂一定有完整的取消稳健三元组。如果调用方传入的臂缺这一组值，规范没有写怎么办；库会把它排除在 $\mathcal F^{\rm rec}_d$ 之外，所有构建都一样。
4. 标了“账单过粗”的臂不进 $\mathcal F^{\rm rob}_d$，也不参加任何取消稳健比较，既不支配别人，也不被别人支配。所以它如果在官方前沿上，就没有臂能在取消稳健值上胜过它，会留在 $\mathcal F^{\rm rec}_d$ 里。
5. 标记以单元的备注为准。前沿结果里另有一份 $\mathcal F^{\rm rec}_d$ 中带标记的臂的列表，列的是其中禁用了稳健支配的臂。这个开关取自各单元的稳健支配标志，不是从备注推出的；对 $\mathcal E_d$ 里的臂，它和备注的结果一致。只因为取消稳健三元组有 $\mathrm{NA}$ 而禁用支配的臂不带标记，按上一条排除在 $\mathcal F^{\rm rec}_d$ 之外。
6. 另有一个辅助函数，返回 $V$ 并列最高的所有臂；测试检查了这些臂都在官方前沿上。
7. 测试用规范的例 6、7、8 从 $\mathcal E_d$ 经过前沿一直核到官方推荐。

### 9. 从回答和使用行为得到权重

*规范 §10。核心 + 桌面五级自报向导。该向导仍使用成对权衡题（甲、乙两个选项）。题面文案在网页视图；elicit 命令调用核心；写入 WeightLedger。窗内改权重仅为试用，不改冻结的正式版本。*

**自报。** 你回答成对的选择题。每道题给出甲、乙两个选项，它们在成本、时间、质量中的两维上此消彼长，第三维相同。用底噪 $c_0$、 $t_0$、 $\epsilon$，甲乙之间的比值为 $\rho_C=(C_A+c_0)/(C_B+c_0)$、 $\rho_T=(T_A+t_0)/(T_B+t_0)$、 $\rho_D=(1-Q_A+\epsilon)/(1-Q_B+\epsilon)$；相同的那一维比值为 1：

$$
s(w)=a\ln\rho_C+b\ln\rho_T+g\ln\rho_D,\qquad
\Delta=\tfrac12\bigl(|\ln\rho_C|+|\ln\rho_T|+|\ln\rho_D|\bigr),\qquad
u(w)=-s(w)/\Delta .
$$

回答分五档：强烈偏好甲（ $+2$）、稍偏甲（ $+1$）、差不多（ $0$）、稍偏乙（ $-1$）、强烈偏好乙（ $-2$）。权重 $w$ 预测的档位是

$$
\ell(w)=\begin{cases}
+2, & u(w)>\delta_2,\\
+1, & \delta_1<u(w)\le\delta_2,\\
0, & |u(w)|\le\delta_1,\\
-1, & -\delta_2\le u(w)<-\delta_1,\\
-2, & u(w)<-\delta_2,
\end{cases}\qquad \delta_1=0.25,\ \delta_2=0.50 .
$$

判档前先把 $u$ 舍入到小数点后 9 位，所以正好等于 $0.25$ 或 $0.50$ 的值仍落在闭区间那一档里。

1. 候选权重是一个网格： $a$、 $b$、 $g$ 各取 $0.05$ 到 $0.90$，步长 $0.05$，并且 $a+b+g=1$，共 171 个点。
2. 题库共 96 题：3 对维度，两维的比值各取 $\{1.3, 1.5, 2, 3\}$ 之一，再分 2 个方向。
3. 记 $m$ 为网格上和你的回答相比最小的总档位偏差。核心区域 $\Omega^{\rm core}_s$ 是偏差等于 $m$ 的网格点，权重区域 $\Omega_s$ 是偏差不超过 $m+1$ 的点，也就是容许其中一题答偏一档。
4. 下一题从没答过的题里选能把 $\Omega_s$ 按五档分得最均匀的那道；并列时取题库里排在前面的。答满 4 题且 $\Omega_s$ 不超过 15 个点，或答满 10 题，就停止出题。
5. 结果以 $\Omega_s$ 和它在每一维上的范围为主。默认点 $w_s$ 是离核心区域重心最近的网格点。
6. $m\ge2$ 时标「回答有矛盾」，并列出在某个核心点上偏差达到两档或以上的题。这个列表可以为空。
7. 题面上的数值逐维从一个基数算出：成本和时间用上一窗的中位数（第一窗取 0.5 元、120 秒），质量用调用方传入的缺陷率。每一维上，在这一维更好的选项显示基数，更差的选项按比值算出，所以成本和时间都为正，缺陷率不会为负；相同的那一维两边都显示基数，浮点误差不超过（基数+底噪）的 1 个 ulp（即该量级上相邻两个浮点数的间隔；这个值同样按比值公式算，比值为 1）。算出的缺陷率会超过 1 的题跳过，不截断。
8. 切点 $0.25$、 $0.50$ 和「容许一题答偏一档」这个误差模型只在模拟里检验过，还没有用真实用户验证。

**行为建议。** 用的是上一窗的选择事件：当时能选哪些臂、你实际选了哪条。只算在至少 2 条臂之间的真实选择；事件里只要有一条臂缺值，整个事件丢弃。用常量表里的底噪 $c_0$、 $t_0$、 $\epsilon$ 和各臂上一窗在该单元的值，记 $x_l=\bigl(\ln(C^{\ast}_l+c_0),\ \ln(T^{\ast}_l+t_0),\ \ln(1-Q^{\ast}_l+\epsilon)\bigr)$，在 $\vartheta\ge0$ 上拟合选择模型：

$$
\Pr(j_e\mid S_e;\vartheta)=\frac{\exp(-\vartheta\cdot x_{j_e})}{\sum_{l\in S_e}\exp(-\vartheta\cdot x_l)},\qquad
w_b=\frac{\hat\vartheta}{\lVert\hat\vartheta\rVert_1},\qquad \hat\lambda=\lVert\hat\vartheta\rVert_1 .
$$

1. 事件少于 20 个、被选过的不同臂少于 2 条、被选臂和每个其他选项的差 $x_{j_e}-x_l$ 组成的矩阵秩小于 3、 $\hat\lambda<0.5$，或者拟合没有明确的最大值，都判为无信号，不出建议。
2. 否则，支持集 $\Omega_b$ 保留剖面对数似然与最大值相差不超过 $3.0$ 的网格点。它只是启发式集合，不是置信区域，也可能为空： $w_b$ 可能不在网格上（某一维低于 0.05），或者似然太尖，连最近的网格点也比最大值低 3.0 以上。 $\Omega_b$ 为空不是错误：有自报时就没有交集，按下表「有自报，没有交集」那一行；没有自报时按「没有自报，行为有信号」那一行。
3. 另做 200 次自助重抽样，报告 $w_b$ 的 5%、50% 和 95% 分位。成功的重抽样不到 100 次时，结果标为「不稳定」。
4. 第一窗给出无信号。用正在打分的窗或更晚的窗的行为会被拒绝并报错。

**两者怎么合并。** 行为从不改权重。答过题时生效的权重是 $w_s$，没答过就各取 $1/3$。行为只额外给出建议：

| 情况 | 生效的权重 | 建议 |
|---|---|---|
| 有自报，行为无信号 | $w_s$ | 无 |
| 有自报， $\Omega_s$ 和 $\Omega_b$ 有交集 | $w_s$ | 「行为和自报一致」，并给出 $\Omega_s$ 里剖面对数似然最高的点 |
| 有自报，没有交集 | $w_s$ | 摆出矛盾，并给出 $w_b$ |
| 没有自报，行为有信号 | 各 $1/3$ | $w_b$ |
| 都没有 | 各 $1/3$ | 提示去答题 |

<summary>实现说明</summary>

1. 离重心最近的网格点有并列时， $w_s$ 取 $(a, b)$ 字典序最小的点。距离用整数精确比较。
2. 核心库只处理比值。题面的金额和时长由比值换算；展示不了的题跳过，之后也不再问。缺陷基数为 0 是合法的。
3. 秩用全主元消元计算，相对容差 $10^{-9}$。「不同的臂」按臂的 id 计数。
4. $\hat\vartheta$ 在 $\vartheta\ge0$ 上用投影牛顿法求。拟合前先查分离：如果有某个方向 $d\ge0$、 $d\ne0$，使每个事件里被选臂都不比每个其他选项差（ $d\cdot(x_l-x_{j_e})\ge0$），就称数据可分。只有差的矩阵秩为 3 时才拟合，所以其中至少一处严格更好，似然沿 $\vartheta+td$ 一直上升，没有最大值：数据可分即不可识别。数据可分、信息矩阵接近奇异或不收敛时，给出「无信号：不可识别」，不报错。
5. 失败的自助重抽样（差的矩阵秩小于 3、数据可分，或拟合不出 $\lVert\vartheta\rVert_1>0$ 的有限结果）跳过并计数。随机种子由调用方传入。
6. $w$ 的剖面对数似然是对数似然 $L$ 沿 $\lambda w$（ $\lambda>0$）的最大值。 $L$ 从 $\lambda=0$ 起不增时取 $\lambda=0$ 处的值。 $\Omega_b$ 的门槛直接用 $L(\hat\vartheta)$， $w_b$ 不投影到网格上。

### 10. 权重敏感性

*规范 §12。核心 + 桌面敏感性面板（胜者图、权重稳健标签、由核心给出的翻转句）。第一窗 / 无锚点层：不显示图。*

这一节看换一组权重结果会怎么变。下面所有计算都在固定的值上做：同一层（或范围内总体）、它的合格臂 $\mathcal E_d$、各臂的成本、时间和质量，以及兜底臂的单元值。下文的 $W_k$ 是第 9 节里当前生效的权重。

**胜者图。** 在第 9 节那 171 个网格点组成的 $G$ 上，对每个点 $w$ 算 $\mathcal E_d$ 里每条臂的价值分 $V_{i,d}(w)$：

$$
{\rm Win}(w)=\{i\in\mathcal E_d:\ V_{i,d}(w)=\max_{l\in\mathcal E_d}V_{l,d}(w)\}.
$$

1. 并列时整组报告，不按名字分先后。
2. 第一个时间窗、参照锚点落 III 档的层，以及没有可比较的臂时，都不出胜者图。这些情况下第 8 节的前沿照常给出。
3. 每个网格点都标出是否在第 9 节的 $\Omega_s$、 $\Omega_b$ 里。这两个集合由调用方传入。
4. 因为 $a$、 $b$、 $g$ 都大于 0，在官方前沿上被支配的臂 $V$ 一定更低，所以胜者组里一定有 $\mathcal F^{\rm off}_d$ 的臂。除了并列容差内的情况（见实现细节），换权重只是在前沿内部换人。
5. 胜者和参照锚点取 I 档实测值还是 II 档夹逼值无关，因为这一项对层内每条臂都一样。更换参照臂或兜底臂可能改变胜者，因为兜底臂的单元值会进入每条臂的分数。

**对权重稳不稳。** 如果你答过题，区域 $\Omega$ 就是 $\Omega_s$。没答过时，取三个权重里和 $W_k$ 相差最大的那一维不超过 $0.10$ 的网格点，边界算在内； $W_k$ 本身不必落在网格上。

1. 对每条臂，报告 $\Omega$ 里它属于 ${\rm Win}(w)$ 的点占多少。并列时每个成员都算这一点，所以各臂占比加起来可能超过 100%。另外还报告它单独获胜的点数。
2. 只有某条臂在 $\Omega$ 的每一点都单独获胜，才标“在你的权重范围内都是它”。每一点都并列不标。

**对抽样稳不稳。** 和上面对权重的检查分开报告。

1. 按任务有放回地重抽样 200 次，在每个（臂, 设计单元）组内抽。每组的任务数不变，所以各臂在每个单元的任务数、冻结的单元权重 $\omega_u$ 和设计网格都不变，变的只是单元内的结果。参照臂和兜底臂和其他臂一样重抽样。调用方传入每个任务的臂和单元以及随机种子，并在每次重抽样里重算 $\mathcal E_d$、各臂的成本、时间和质量，以及锚点。
2. 结果给出每条臂有多少次属于 ${\rm Win}(W_k)$、有多少次在 $\mathcal F^{\rm off}_d$ 上。并列时每个成员都计数，并报告并列的次数。参照落 III 档或 $\mathcal E_d$ 为空的那次没有胜者，但前沿照常计数。
3. 同一个种子得到同样的结果。
4. 应用的种子从哪里来，等接入数据层时再定；库把种子当作输入，并在结果里报告。

**翻转线。** 取 $W_k$ 下 $V$ 最高的两条臂 $i$ 和 $j$：

$$
\Delta_C=\ln\frac{C_i^{\ast}+c_0}{C_j^{\ast}+c_0},\qquad
\Delta_T=\ln\frac{T_i^{\ast}+t_0}{T_j^{\ast}+t_0},\qquad
\Delta_D=\ln\frac{1-Q_i^{\ast}+\epsilon}{1-Q_j^{\ast}+\epsilon},\qquad
a\Delta_C+b\Delta_T+g\Delta_D=0 .
$$

在左边大于 0 的那一侧， $j$ 领先 $i$。

1. 少于 2 条臂，或者第二、第三名并列时（包括三条及以上的臂并列第一），不画线。如果第一、第二名现在就并列，线照画，并标为并列。
2. 每一维各用一句话说明这条线：把这一维的权重固定在当前值，另外两维变化，各自不低于 0.05。前端选用哪一句。
    1. 翻转点在这个范围里：“只要时间权重超过成本权重的 $r$ 倍， $j$ 就会超过 $i$”（两维的先后按方向排好）。
    2. 在这个范围里 $j$ 始终不领先： $j$ 不会超过 $i$。
    3. 在这个范围里 $j$ 始终领先：在允许的权重下 $j$ 都更高。如果前两名目前的差距在并列容差内，这句后面会加上“（当前差距在并列容差内，按 id 排序）”。
    4. 在这个范围里一直并列：两者始终并列。
3. $r$ 向上取整到 2 位小数，所以印出来的条件一定够用。每句话末尾都加上“这是在当前估计值下的结论”。

**对底噪稳不稳。** $W_k$ 下的胜者算 7 次：一次用设定的底噪，另外把 $c_0$、 $t_0$、 $\epsilon$ 逐个减半、加倍各算一次。7 次胜者都相同就标“底噪稳健”，否则逐次列出胜者。这只是诊断，展示的分数仍用设定的底噪。

<details>
<summary>实现细节</summary>

1. 核心函数一次处理一层或一个总体。调用方对一个范围的每一层和每个总体分别调用。
2. 网格按精确的二十分之一生成，和第 9 节的生成方法相同。目前本模块自己生成一份，以后改为调用第 9 节的网格代码（计划中）。
3. 传入 $\Omega_s$ 或 $\Omega_b$ 时，每个点都要在 0.05 的网格上（容差 $10^{-9}$），且没有重复，否则报错。
4. 没有自报时 $\Omega_s$ 传“无”。按定义 $\Omega_s$ 不会为空（它含与答案最吻合的点），所以传空集报错。
5. 行为没有信号时 $\Omega_b$ 传“无”。 $\Omega_b$ 为空表示行为有信号、但没有网格点够格（见第 9 节），照常接受，不标任何点。结果会说明是哪种情况：没有信号、没有网格点，或有几个点。
6. $\Omega$ 的距离比较带 $10^{-9}$ 的容差，所以正好相差 $0.10$ 的点算在内。 $W_k$ 各为 1/3 时， $\Omega$ 有 12 个点。
7. 重抽样用 xorshift64 随机数，下标用拒绝采样，没有取模偏差。种子为 0 报错。所有计数都用带检查的加法，溢出就报错。
8. 并列用的容差和正式推荐相同（ $V$ 上 $10^{-12}$）。所以一条只被支配一点点的臂，可能和支配它的臂落在同一个并列组里，整组照报。每个胜者组都会检查是否含 $\mathcal F^{\rm off}_d$ 里的臂，不含就报错。
9. 第一、第二名并列时， $i$ 和 $j$ 按臂的 id 排先后。这只决定展示顺序，不决定谁是胜者。
10. 结构体里保留没取整的比值 $r$，只有印出来的值向上取整。和某个两位小数相差不到 $10^{-11}$ 时就印成那个数，所以 1.1 印成 1.10，不是 1.11。
11. 底噪检查以这个范围设定的底噪为基数减半、加倍。
12. 规范里两条臂的例子写成了测试：网格上 Y 赢 93 个点，X 赢 78 个点；在一组如实作答得到的 14 点 $\Omega_s$ 里，Y 14 点全赢。

### 11. 探针和中转站检查

*规范 §11。核心 + 本地运行脚本 + 桌面探针同意/已记录结果。核心只判定已经记录下来的交换，自己不发请求。首次同意存本地。预算和观察期文案来自核心常量。观察期未完成前档位仅供参考。页面可展示此前已记录或回放的探针结果，包括仓库内回放夹具。同意之后、且一次探测就绪时，可以对选定的一条臂手动跑一次。打开窗口不会自动探测。外壳可以在已同意且未超过月预算时发送，并把判定结果和暂定花费写入存储。可以启用应用内定时重跑，间隔暂定为 24 小时（`PROBE_SCHEDULE_INTERVAL_MS`）。启用时不发送，第一次在一个间隔之后。错过的间隔不补跑。月预算停止后不再定时发送。退出应用即停止。这不是操作系统的定时任务，也不是后台守护进程。*

这一节检查一条路线提供的是不是它声称的模型。探针结果只用于第 6 节第 4 道门槛里的真实性，从不计入任何分数；下面的日志完整性检查看的是窗内记录下来的请求。

**探针集。**

1. **确定性类**，10 题：加法、减法、乘法、取余、数字串倒序、转大写、五个数取最大、四个数排序、数字母 a 的个数、各位数字之和。题里的数由种子生成（种子为 0 时报错），用拒绝采样，没有取模偏差。每题有两种措辞，由种子决定；排序题不会给出已经排好的列表。
2. **指纹类**，10 题，每题只答一个 token，各采样 20 次：随机数、颜色、字母、水果、动物、1 到 10 之间的数、国家、星期几、行星、乐器。
3. **能力类**：工具调用（`record_number`，参数必须恰好是 `{"n":<数>}`，比较前忽略空白）、严格 JSON（回复正文必须恰好是 `{"answer":<数>}`（比较前忽略空白），包在代码块里也算不符）、回传 thinking 签名（只在 Anthropic 协议上、且路线声称支持时才查）、长上下文回忆（每月一次）。只查路线声称支持的项；一项都不声称，这一类就不适用。
4. 探针按随机顺序发送，请求之间随机停 1 到 4 秒。这一步由本地脚本完成。

**单类判定**，以北京时间的运行日为单位：

1. 确定性类答对 9 题及以上通过，7 题及以下不通过，8 题不确定。指纹类 10 题里 8 题及以上一致通过，5 题及以下不通过，6、7 题不确定。这些阈值都是暂定值，等观察期校验。
2. 遇到 429 限流、超时、其他 HTTP 错误或无法解析的回复，这一题算“未作答”，不算错。只有未作答的题不论怎么算都不改变结论时，才给出通过或不通过，否则为不确定。
3. 指纹类用 Jensen-Shannon 散度（以 2 为底）和官方基线比较，基线的两次运行合并成一个分布。阈值 $\tau_{\rm JS}$ 取两次基线运行之间逐题散度的 95% 分位（最近秩），10 题时就是最大的那个。基线超过 30 天，或者模型版本、协议、采样参数有一项不同，都视为没有基线，这一类判为不确定。基线键里的采样参数只去掉首尾空白，不改大小写。规范写法是小写的 `key=value`，多项按固定顺序拼接，例如 `temperature=1`。`Temperature=1` 和 `temperature=1` 是不同的键，这一类会判为不确定，而不是不通过。
4. 硬失败：返回的 model 属于其他模型族；usage 里出现只有其他厂商才用的字段名（模型自己厂商的命名和所用协议的命名都允许）；适用时（Anthropic Messages 协议，且路线声称支持 thinking），回传的 thinking 签名被拒（HTTP 400）。其他协议下或没声称 thinking 时，同样的 400 不算硬失败。
5. 模型名先去首尾空白并转小写，再查别名表（键是小写；命中的别名值也会去首尾空白并转小写），再去掉末尾的日期（YYYYMMDD、YYYY-MM-DD 或 MMDD）。去掉版本段就是模型族，例如 `claude-haiku-4-5` 属于 `claude-haiku`。调用方自备的模型族前缀表和官方主机表在使用时同样处理：前缀、主机和厂商名都去首尾空白并转小写，所以 `Anthropic` 和 ` API.Anthropic.com ` 与 `anthropic`、`api.anthropic.com` 的分类结果相同。修剪后为空的项忽略。仍是最长前缀优先。

**档位**，每条臂每个时间窗判一次，先命中的为准：官方直连（不给档；主机在官方主机表里，且厂商一致），然后依次是 C、A、A−、B。官方直连的臂如果在窗内有硬失败（来自探针或被动日志），另外标上“官方路线异常”供排查，不影响它的状态，也不挡门槛。

1. **C**（与基线不一致的嫌疑）：硬失败出现在 2 个及以上运行日，或确定性类在 2 个及以上运行日不通过，或指纹类在 2 个及以上运行日不通过。能力类不通过不计入 C。
2. **A**：确定性类、指纹类、能力类各在 2 个及以上运行日通过，没有硬失败，且能力类不通过日不超过 1 个。能力类不适用的运行日算作通过。
3. **A−**：确定性类和能力类各至少在 1 个运行日通过，没有硬失败，指纹类不是「0 个通过日且至少有 1 个不通过日」（没跑、只有不确定、或至少有 1 个通过日都可以），且能力类不通过日不超过 1 个。这里能力类不适用的运行日同样算作通过。
4. **B**（未验证）：其余全部。

能力类在 2 个及以上运行日不通过、且还没到 C 时，档位是 B。

**真实性门槛。** 官方直连、A、A− 通过，C 不通过。开启探针时 B 不通过；关闭探针时 B 通过，并标上“未验证（探针已关闭）”。观察期校验通过之前，档位只做展示：所有判了档的臂都通过这道门槛，并标上“真实性未定”。按设计，观察期用一条官方直连路线做正对照、一个较小的模型做负对照，各跑满 2 个运行日；目前还没有跑过（见第 12 节）。展示的是判定结果的真实状态，所以官方直连的臂不会显示成 A。

**日志完整性门槛**，全部按整数比较：

1. 窗内至少 95% 的请求可以解析。
2. 同一模型族内版本不符的请求最多占 5%。分母是可解析的请求去掉缺 model 的和其他模型族的；分母为 0 时这一条通过。
3. 缺 model 的请求超过可解析请求的 20% 时，只标上“无法核对返回模型”。
4. 其他模型族的请求已经算作硬失败，不重复计数。
5. 窗内没有请求时通过，并标上“无请求可核对”。

**探针月预算**（规范 §9）：按北京时间的自然月计，默认 10 元。本月已花加上这次的估价不超过预算才跑，已花达到预算就停（9.99 + 0.01 可以跑，9.99 + 0.02 停）。

**路线开销**（只作诊断，不计入 $T^{\ast}$）：同一模型、同一探针，只留下与至少一个路线样本相距不超过一小时的官方样本（正好一小时也算）。首 token 时间、总时长、输出速度各自用全部路线样本的中位数减去留下的官方样本的中位数。

### 12. 计划中

规范的以下部分尚未实现：

1. **第 10 步的其余部分**： $R_k$ 或 $F_k$ 更换时并排展示旧结果和新结果（§13）；失败后提示你通常会换去某条臂 X、要不要把 X 设为兜底（§13）；跨评分范围的描述性合计（§6）。
2. **第 13 步的其余部分**：观察期的实际运行（阳性对照和阴性对照）。探针运行库可以通过 HTTP 采集官方直连指纹基线并写入本地存储；测试使用模拟服务器，没有桌面按钮。超过 30 天的基线仍视为没有基线。尚未实现的还有：被动日志里的硬失败日；操作系统级定时任务或后台守护进程；生成 thinking 签名请求和长上下文请求。外壳已经可以在已同意且未超过月预算时对选定的一条臂发一次探测，写入判定结果，并记下暂定花费。页面可以手动跑这一次。也可以启用应用内定时重跑，间隔暂定为 24 小时（`PROBE_SCHEDULE_INTERVAL_MS`）：只有启用之后才开始，第一次发送在一个间隔之后，错过的间隔不补跑，月预算停止后不再定时发送，退出应用即停止。探针档位阈值仍为暂定。

## 使用

### 给用户

本地 Tauri 桌面应用可以列出和添加臂，展示编程范围时间窗结果（前沿、资格、推荐、真实性来源和权重来源），运行五级自报向导，打开敏感性面板，记录探针同意，并展示此前已记录或回放的探针结果。同意之后、且一次探测就绪时，可以手动跑一次。可以启用应用内定时重跑（间隔暂定 24 小时）；启用时不发送，退出应用即停止。打开窗口不会自动探测。观察期未完成前档位仍仅供参考，并标「真实性未定」。桌面应用把数据存在本机。当前不提供安装包；运行需从源码构建（见下文）。

### 给开发者

核心库和存储库（不需要系统 GUI 库；内置 SQLite 需要 C 编译器）：

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

网页前端（Node.js 20 及以上）：

```sh
cd web
npm ci
npm run lint
npm run typecheck
npm test
npm run build
```

对真实中转站跑探针（开发者用；CI 从不联网）。先按种子和模型打印请求体（不含答案），再发送并记录回复，最后判定：

```sh
cargo run -p agent-value-core --example probe_plan -- <seed> <model> [tool,json|tool|json|none] > plan.jsonl
python3 tools/probe_live.py --base https://<relay> --key-env <VAR_NAME> --plan plan.jsonl --replay replay.tsv --log run.jsonl
cargo run -p agent-value-core --example probe_judge -- <seed> <model> replay.tsv [tool,json|tool|json|none]
```

`tools/probe_live.py` 只用 Python 标准库。key 只从指定的环境变量或本地被 git 忽略的 `.env` 读取，从不写进任何输出：写之前会检查原文、转义后的文本和 JSON 转义形式。如果在要写的内容里发现 key，脚本会拒绝写入并退出。脚本不记录请求头。`--base` 必须是 https，本机的模拟服务器除外。

`agent-value-probe-run` 里的 `collect_fingerprint_baseline` 采集官方直连指纹基线。它是库函数：没有命令行入口，也没有桌面按钮。调用方传入官方直连的 OpenAI Chat Completions 臂、主机与该臂路线主机相同的 `https` 基址（例如 `https://api.openai.com`，模型 id 由调用方选定）、bearer token 的环境变量名、同意标志、预算快照（交给 `probe_budget` 的 `spent` 和 `budget`）、时钟和存储。token 从该变量或 `./.env` 读取，不写入存储。调用会发送 10 道指纹题，每题 20 个样本，共两轮，温度为 1（top_p 为 1，max tokens 为 64）。这不是确定性探针所用的温度 0。然后 upsert 一条基线。存下的 `provider` 是臂上路线主机的原样，`model_revision` 为空。未同意、预算停止、主机被拒绝、不是官方直连或密钥不可用时，不发送也不写入。任一次失败、超时或无法解析的样本都不写入。暂定价是每个样本 0.02 元，400 个样本共 8 元，低于 10 元的月预算上限。`spent` 是调用方交给这道门的参考输入。这条路径不写入探针花费。这不跑观察期，也不改档位阈值。

`agent-value-probe-run` 可以在已保存同意且未超过月预算时，对选定的一条臂做同样的一次探测。单飞锁和预算检查都是本进程内的。探针面板的 `sends_http` 为 true，因为 `run_probe_once` 可以发送。窗口只在已同意且 launch 为 ready 时提供手动运行，打开时不会自动跑。应用内定时可以用同一条路径稍后重跑：启用前不发送，第一次在暂定的 24 小时间隔之后，月预算停止后不再发送，退出应用即停止。这不是操作系统的定时任务。

桌面外壳：`src-tauri/` 是单独的 Cargo 包，这样测试核心库时不需要 GUI 库。构建它需要 Tauri 2 的系统依赖（Linux 上是 WebKitGTK 4.1 及相关开发包）。先构建网页前端，再进入 `src-tauri/` 运行 `cargo build`。本地启动可运行 `cargo tauri dev`，或运行构建出的二进制。CI 会安装这些依赖，并对外壳运行 `cargo check` 和 `cargo clippy`。外壳已包含上文所述的时间窗结果、自报、敏感性和探针同意/结果界面。当前不提供分发用安装包。

## 密钥和隐私

真实的 API key 只放在本地 `.env` 文件里，该文件已被 git 忽略。`.env.example` 只列变量名。agent-value 只保存一条路线所用环境变量的名字，从不保存它的值；数据库里没有存 key 值的列。

所有数据都在一个本地 SQLite 文件里。提示词和代码文本从不保存：只存类别、长度，以及一个 HMAC-SHA256 摘要，摘要的密钥放在数据库之外。任务级数据 180 天后清除，存储层可以导出全部数据，也可以删除全部数据。
