# agent-value

[English](README.md) | 简体中文

agent-value 是一个给个人用的本地桌面工具。它按成本、时间和质量，给你实际在用的（模型，路线）组合打分，三者的权重按你自己的偏好来定。它不是公开排行榜：每个数字都来自你自己的任务，所有数据都只留在你自己的电脑上。

打分规则依据一份成文的规范（v22），规范没写清的地方另有一份决策记录补上。这两份文件都不在本仓库里；本 README 只讲已经实现的部分。

## 基本概念

- **打分范围。** 每类任务单独打分。默认有两个范围：编程和非编程。不同范围的分数从不合并。
- **臂（arm）。** 被比较的单位：一个模型加一条路线。路线包括 API 主机、协议（例如 Anthropic Messages 或 OpenAI Chat Completions）和所用的 agent 或客户端。三者中任何一项不同，就是另一条臂。同一条路线上换 API key 不算新臂。
- **单元和层。** 任务按子类分进单元 $u$ （编程默认分为：修复、新增、重构、解释与审查、其他）。默认只有一层；也可以按任务规模（小、中、大）把任务分成层 $d$，规模只按你自己的输入来量，这时一个单元就是某层里的一个子类。每个单元有一个权重 $\omega_u$，等于上一窗里该单元在本层任务中所占的份额。
- **任务。** 从你提交到交付、放弃或取消为止的一段过程。
- **时间窗。** 打分以 30 天为一窗。每窗开始时，单元权重、你的权重版本、价目表和分类规则都按之前的数据冻结；参照臂和兜底臂选定以后也同样冻结（选取规则是第 10 步，计划中）。第一窗不给出 $V$，库里已经实现了这一点。按规范，第一窗仍要展示各臂的成本、时间、质量和前沿，并标明“尚未校准”，库里现在已经能算前沿，但带这个标注的展示还在计划中。
- **参照臂 $R_k$ 和兜底臂 $F_k$。** $R_k$ 是所有其他臂都要拿来比较的那条臂。一条臂失败 $K$ 次后，任务交给 $F_k$；默认 $F_k=R_k$。参照臂和兜底臂自身不再往下交给别的臂。

## 打分原理

记号： $i$ 表示臂， $u$ 表示单元， $d$ 表示层。含义清楚时省略下标；除非另有说明，每个量都按“每条臂、每个单元”计算。 $\mathrm{NA}$ 表示“无定义”，代码从不把它当成 0。

### 1. 任务结果和质量信号

*规范 §3.1。已实现。*

每个任务只得到一个结果。规则从上往下检查，第一条成立的规则说了算：

1. 你明确中止了任务：**取消**。
2. 任务运行过检查（测试、构建、类型检查），且最后一次检查失败：**失败**。
3. 任务结束后 30 分钟内，你在同一会话或同一工作目录里发了一条消息，冻结的分类器判定为返工或纠正：**失败**。提新功能不算返工。
4. 编程任务的改动在 24 小时内被全部回滚：结果事后**改判为失败**。
5. agent 报告完成，最后一次检查（如果有）通过，且第 3、4 条都没触发：**成功**。
6. 其他情况（日志不完整、没有完成信号、会话中断）：**未定**。未定永远不算成功。

30 分钟的返工窗口结束前，结果都只是暂定；编程任务还要等 24 小时的回滚窗口结束。由这些结果得到每个单元的计数： $n^1$ （成功）、 $n^0$ （失败）、 $n^C$ （取消）和 $m$ （未定）。

质量 $q_j\in[0,1]$ 只在成功的任务上量，而且只来自你的评分：1-5 星对应 $q_j=(s-1)/4$。为了避免只有出了问题的任务才被打分，核心库会从成功的任务里随机挑 10% 发起评分请求，每天最多 3 次（按北京时间）；真正向你发出评分请求的界面还在计划中。改动保留了多少从不当作质量，因为那样会奖励小改动、惩罚合理的重构；它只用作诊断。

每一层每一窗采用以下两种质量模式之一：

- **评分模式**：调用方传入的候选名单里（这份名单应当就是第 6 节的资格集合 $\mathcal E_d$，但库里还没把两者接起来），每条臂在每个正权重单元里都至少有 3 条评分。参照臂或兜底臂只有本身是候选时才计入。评分会向一个合并均值 $q_B$ 收缩（上一窗该单元所有臂的均值，没有就取 $0.5$）：

$$
\hat q=\mathrm{clip}\!\left(\frac{\sum_{j=1}^{n_q}q_j+m_0q_B}{n_q+m_0},\ 0.01,\ 0.99\right),\qquad m_0=0.5 .
$$

- **成功率模式**：其他情况。本层每条臂，包括参照臂，都取 $\hat q=0.99$，于是 $Q^{\ast}$ 就变成成功交付的概率。结果会照此标注（和展示功能一起实现，计划中），而不是把缺数据当成平均质量来展示。

### 2. 单元权重和单元状态

*规范 §0。已实现。*

**单元权重。** 对第 $t$ 窗， $\omega_u$ 等于第 $t-1$ 窗里你在单元 $u$ 的任务数，除以你在整层的任务数。按任务数算，不按成本或时间，探针任务不计入。如果该层上一窗没有任务，就沿用上一份有效权重；如果也没有，就给配置好的各子类平均分配权重。下文所有计数和打分都只用 $\omega_u>0$ 的单元。设计里预留了一个单独的探针单元，权重恒为 0（探针本身还在计划中，第 13 步）。

**单元状态。** 每条臂的每个正权重单元，都恰好处于一种状态：

$$
\mathrm{miss}:\quad n^1+n^0=0,
$$

$$
\mathrm{fail}:\quad n^1+n^0>0\ \wedge\ \bigl(n^1+n^0<3\ \vee\ p_K^{lo}<0.75\ \vee\ p_K^{C,lo}<0.75\bigr),
$$

其余情况为 $\mathrm{valid}$ （有效）。处于 fail 状态的单元分两种，按以下顺序判断：

- $F_{\rm thin}$ （样本太少）： $n^1+n^0<3$。这时不检查悲观通过率，因为样本这么少时它不可靠。
- $F_{\rm bad}$ （确实失败）： $n^1+n^0\ge3$，且 $p_K^{lo}<0.75$ 或 $p_K^{C,lo}<0.75$。

$p_K^{lo}$ 和 $p_K^{C,lo}$ 在下一节定义。代码还会按层统计各状态的单元数，并把它们的权重加总；参照臂用的是完全相同的规则。在 $\mathrm{miss}$ 单元里， $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$ 及其抗取消版本都是 $\mathrm{NA}$。

### 3. 通过率和重试

*规范 §1。已实现。*

对每条臂的每个单元，这些量给出该臂在自己的 $K$ 次尝试内完成任务的概率，以及途中预计会失败几次。

**先验。** 每个单元从一个基础通过率 $p_B$ 出发：有直接基准就用直接基准，没有就用同层均值，再没有就取 $0.5$。先验强度 $\kappa$ 决定 $p_B$ 相对于你自己的结果占多大分量：

$$
\kappa=
\begin{cases}
n_B, & \text{direct pooling } (\rho=1),\\[2pt]
\dfrac{\kappa_p\,n_B}{\kappa_p+n_B}, & \text{discounted } (0\le\rho<1),\\[6pt]
\min(\kappa_p,3), & \text{same-layer mean used for } p_B,\\
0, & \text{no benchmark and no layer mean (Jeffreys)},
\end{cases}
\qquad \kappa_p=20\rho .
$$

$n_B$ 是基准的样本量， $\rho$ 表示基准和你自己的任务有多接近。 $\kappa$ 在 $\rho=1$ 处有跳变；这是照规范写的，已列为待定问题。

**后验首次通过率。**

$$
\alpha=\kappa p_B+n^1+0.5,\qquad
\beta=\kappa(1-p_B)+n^0+0.5,\qquad
p_1=\frac{\alpha}{\alpha+\beta}.
$$

$+0.5$ 是 Jeffreys 半计数，所以完全没有先验（ $\kappa=0$）时，臂从 $\mathrm{Beta}(0.5,0.5)$ 出发。取消和未定的任务不计入 $\alpha$ 或 $\beta$。

**重试。** 一条臂自己最多尝试 $K=3$ 次。失败以后，每多试一次，成功的概率是 $\pi$。目前 $\pi$ 由调用方传入；从你的数据中估计它还在计划中。如果 $K$ 次全部失败，任务交给兜底臂 $F_k$，它最多再试 $K$ 次，所以每个任务最坏要试 $2K=6$ 次。

$$
q_K=(1-p_1)(1-\pi)^{K-1},\qquad p_K=1-q_K,
$$

$$
E[n_F]=(1-p_1)\sum_{j=0}^{K-1}(1-\pi)^{j},\qquad
E[n_W]=E[n_F]-q_K .
$$

| 符号 | 含义 |
|---|---|
| $p_K$ | 该臂在自己的 $K$ 次尝试内成功的概率 |
| $q_K$ | 该臂自己的 $K$ 次尝试全部失败、任务被转交的概率 |
| $E[n_F]$ | 该臂自己失败次数的期望 |
| $E[n_W]$ | 重试前等待次数的期望。前 $K-1$ 次里每失败一次，后面都会再试一次，不管那次结果如何。第 $K$ 次失败直接转给兜底臂，没有等待，所以不计入。 |

这四个量都只描述该臂自己的尝试，不含兜底臂内部的重试。兜底臂的成本、时间和质量，在第 4 节里通过 $q_K$ 项按每个任务计入一次。

**悲观通过率和抗取消版本。** 单元状态判定用的是 $p_1^{5\%}=\mathrm{Beta}^{-1}(0.05;\alpha,\beta)$ 和 $p_K^{lo}=1-(1-p_1^{5\%})(1-\pi)^{K-1}$。抗取消版本把取消算作失败，即 $\tilde n^0=n^0+n^C$，再用同样的公式重新算 $p_1^C$、 $p_K^C$、 $q_K^C$、 $E^C[n_F]$、 $E^C[n_W]$ 和 $p_K^{C,lo}$。

<details>
<summary>实现说明</summary>

- 先算 $q_K$，再令 $p_K=1-q_K$，这样 $p_K+q_K=1$ 严格成立。 $E[n_F]$ 逐项求和，不用闭式 $(1-p_1)\frac{1-(1-\pi)^K}{\pi}$；这样 $\pi$ 极小时不会出现相消误差， $\pi=0$ 时也不用特殊处理，此时结果就是 $K(1-p_1)$。
- 不合格判定不对 Beta 分布求逆。它先算 $x^{\ast}=1-0.25/(1-\pi)^{K-1}$；若 $x^{\ast}\le0$ 则单元通过，否则当 $\mathrm{BetaCDF}(x^{\ast};\alpha,\beta)>0.05$ 时判为不合格。这与 $p_K^{lo}<0.75$ 等价。分位数用对 CDF 二分的方法求出，只用于展示。不完全 Beta 函数在本 crate 里自己实现。
- 先验用一个显式的枚举来选（`DirectPool`、`Discounted(ρ)` 且 $\rho\in[0,1)$、`LayerMean`、`Jeffreys`），而不是拿 $\rho$ 和 1 比大小。`Discounted` 在 $\kappa_p+n_B=0$ 时给出 $\kappa=0$；`Discounted(1.0)` 和 $\rho<0$ 都返回错误。

</details>

### 4. 单元的成本、时间和质量： $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$

*规范 §2-§3。已实现。*

把一个单元里的一个任务交给某条臂，算上重试、取消和转交，这三个量分别是期望成本、期望活跃时间和期望交付质量。

**输入。** 一个任务的成本 $c$，有实际扣费时就用它所有请求的实际扣费（中转站余额变化或账单明细，按调用 ID 去重），没有就用 token 用量（输入、输出、缓存读、缓存写，含中转站倍率）乘以冻结的价目表，再没有就是 $\mathrm{NA}$。库接收的成本已经折算成人民币；下面几条是给负责汇总成本的一方定的输入约定（汇总本身还在计划中）。订阅制路线按该任务占当月 token 的份额分摊月费；赠送额度按价目表计价，不算 0；分类器和判分模型的费用不计入。时间 $t$ 指活跃时间：挂钟时间减去等你的时段（权限确认、向你提问）。等待时长和打断次数会作为诊断信息和 $T^{\ast}$ 并排展示（和展示功能一起实现，计划中）。

**两侧均值。** 对每一侧（成功任务、失败任务），记 $m_S$ 或 $m_F$ 为这一侧取值不是 $\mathrm{NA}$ 的任务数，所以 $m_S\le n^1$， $m_F\le n^0$。用 $m^{\prime}$ 统称这两个数。均值先做缩尾： $m^{\prime}\ge10$ 时，把最大的 $k(m^{\prime})=\max(1,\lfloor0.01m^{\prime}\rfloor)$ 个值和最小的 $k$ 个值，分别替换成剩余值中离它们最近的值； $m^{\prime}<10$ 时直接用原始均值，并标明未缩尾。然后再向基准收缩：

$$
\tilde C_S=\frac{m_S\bar C_S^w+\kappa_C C_S^B}{m_S+\kappa_C},\qquad
\tilde C_F=\frac{m_F\bar C_F^w+\kappa_C C_F^B}{m_F+\kappa_C},\qquad
\kappa_C=5 .
$$

时间用同样的公式。没有基准时不做收缩， $\tilde C=\bar C^w$。如果某一侧没有样本，它的值依次退回直接基准、该臂在本层的合并均值，最后是 $\mathrm{NA}$。

**成本。**

$$
C^*_{iu}=p_{K}\tilde C_{S}+E[n_F]\tilde C_{F}
+q_{K}\,C^*_{F,u}
+\frac{n^C\hat{\bar C}_{C}}{n^1+n^0} .
$$

从左往右依次是：成功那次尝试的成本、失败尝试的成本、转交给兜底臂的成本，以及把取消任务的成本摊到已完成任务上的部分。 $\hat{\bar C}_C$ 是一个取消任务的平均成本；没有取消账单时，依次退回 $\max(\tilde C_F,\ \text{layer pool})$ （layer pool 即本层合并值）、 $\max(\tilde C_F,\ C_F^B)$，最后是 $\mathrm{NA}$。参照臂和兜底臂自身的转交项为 0，因为它们是最后一站。

**时间。**

$$
T^*_{iu}=p_{K}\tilde T_{S}+E[n_F]\tilde T_{F}
+E[n_W]D+q_{K}T^*_{F,u}
+\frac{n^C\bar T_{C}}{n^1+n^0} .
$$

$D$ 是一次失败到下一次重试之间的间隔。缺这个值时先用本层的合并值，再用基准；两者都没有时，时间不可比，也不出总分。

**质量。**

$$
Q^*_{iu}=p_{K}\hat q+q_{K}\bar Q_{F},\qquad
\bar Q_{F}=\frac{f\,Q^{\rm match}+\kappa_F Q^*_{F,u}}{f+\kappa_F},\qquad \kappa_F=5 .
$$

$\bar Q_F$ 是该臂失败后由兜底臂完成任务时得到的质量：在 $f$ 个配对样本上观察到的质量，向兜底臂自己在该单元的质量收缩。参照臂和兜底臂自身的转交项为 0： $Q^{\ast}_{R,u}=p_K\hat q$。

**缺失的数据不补。** 如果参照臂在某个单元的某一维因任何原因是 $\mathrm{NA}$，那么所有臂在该单元的这一维都是 $\mathrm{NA}$。当 $F_k\ne R_k$，且兜底臂有任何一维是 $\mathrm{NA}$ 时，候选臂在该单元的三维全部是 $\mathrm{NA}$。不存在另一个去掉转交项的“裸”成本。

**抗取消版本。** 这里把 $p_K$、 $q_K$、 $E[n_F]$ 换成抗取消的值，并把取消项换成取消任务超出一次正常失败的那部分额外成本：

$$
C^{*,C}_{iu}=p^C_{K}\tilde C_S+E^C[n_F]\tilde C_F+q^C_K C^*_{F,u}
+\frac{E_{C}}{n^1+n^0},
$$

$$
E_{C}=
\begin{cases}
\displaystyle\sum_{j\in\mathcal C}\max\bigl(0,\ c_j-\tilde C_{F}\bigr), & \text{per-task bills},\\[8pt]
E^{UB}_{C}, & \text{aggregate bill with a per-task cap},\\[4pt]
E^{LB}_{C}, & \text{aggregate bill with no cap, or no cancel bills},
\end{cases}
$$

$$
E^{LB}_{C}=n^C\max\bigl(0,\bar C_{C}-\tilde C_{F}\bigr),
$$

$$
E^{UB}_{C}
=\left\lfloor\frac{S_{C}}{U}\right\rfloor\max\bigl(0,\ U-\tilde C_{F}\bigr)
+\max\!\left(0,\ S_{C}-\left\lfloor\frac{S_{C}}{U}\right\rfloor U-\tilde C_{F}\right),
\qquad S_{C}=n^C\bar C_{C}.
$$

$U$ 是单个任务的扣费上限， $S_C$ 是取消任务的账单总额。 $E^{UB}$ 是在已知总额和上限的情况下额外成本可能的最大值； $E^{LB}$ 是下界。只有下界可用时，该单元会被标记，并关闭抗取消比较。时间用同样的公式。最后用一道单调性保护，保证抗取消版本永远不会比普通版本更好：

$$
C^{*,C}\leftarrow\max(C^{*,C},C^*),\qquad
T^{*,C}\leftarrow\max(T^{*,C},T^*),\qquad
Q^{*,C}\leftarrow\min(Q^{*,C},Q^*),
$$

其中 $Q^{\ast,C}_{iu}=p^C_K\hat q+q^C_K\bar Q_F$。

<details>
<summary>实现说明</summary>

- 规范把 $E^{UB}$ 的第一项写成 $\lfloor S_C/U\rfloor(U-\tilde C_F)$，当 $U<\tilde C_F$ 时它会变成负数。代码对这一项取了 $\max(0,\cdot)$。当 $U\ge\tilde C_F$ 时两者一致。在 $S_C$ 恰好是 $U$ 的整数倍处，表达式是连续的，所以 $\lfloor S_C/U\rfloor$ 不加容差。
- $E^{UB}$ 只在 $0\le S_C\le n^CU$ 时有定义。超出这个范围时，单元计算返回错误，不返回数字； $S_C=n^CU$ 是允许的。 $n^C=0$ 时账单必须为空；如果给了上限，上限必须为正。
- 成本或时间为 $\mathrm{NA}$ 的任务不进入该维的样本； $p_K$ 仍用完整的 $n^1$ 和 $n^0$。“本层合并值”指该臂在本层所有正权重单元的原始样本合在一起做缩尾。库从调用方接收这个合并均值；从本地数据库里算出它还在计划中。取消时间 $\bar T_C$ 的退回顺序和成本相同。
- 如果 $f>0$ 但缺 $Q^{\rm match}$，质量为 $\mathrm{NA}$；如果 $f=0$，则 $\bar Q_F=Q^{\ast}_{F,u}$。
- 溢出或出现 NaN 时返回错误。任何一维是 $\mathrm{NA}$ 时，抗取消比较的标记都是关闭的。

</details>

### 5. 聚合和价值分 $V$

*规范 §4。已实现；第 10 步完成前，参照锚点由调用方传入。*

先用单元权重对单元值求加权平均，再用层权重对层值求加权平均：

$$
C^*_{i,d}=\sum_{u\in d^+}\omega_uC^*_{i,u},\qquad
C^*_i=\sum_{d\in D^+}\omega_dC^*_{i,d},
$$

$T^{\ast}$ 和 $Q^{\ast}$ 同理。 $d^+$ 和 $D^+$ 是权重为正的单元和层。只要有一个正权重单元是 $\mathrm{NA}$，聚合结果就是 $\mathrm{NA}$；剩下的单元不会重新分配权重。

价值分把一条臂和参照锚点在三维上同时比较：

$$
V_{i,d}=100
\left(\frac{C^{\rm ref}_{R,d}+c_0}{C^*_{i,d}+c_0}\right)^{a}
\left(\frac{T^{\rm ref}_{R,d}+t_0}{T^*_{i,d}+t_0}\right)^{b}
\left(\frac{1-Q^{\rm ref}_{R,d}+\epsilon}{1-Q^*_{i,d}+\epsilon}\right)^{g}.
$$

- $V=100$ 表示整体和参照一样好。高于 100 更好，低于 100 更差。
- 每个因子都是“参照比本臂”的比值，所以成本更低、时间更短、缺陷（ $1-Q^{\ast}$）更少，都会让 $V$ 变大。
- $a$、 $b$、 $g$ 是你给成本、时间和质量的权重，来自当前的权重版本。三者之和为 1，每个至少 $0.05$；没有任何依据时各取 $1/3$。
- $c_0=0.15$ 元、 $t_0=15$ 秒和 $\epsilon=0.02$ 是底噪。它们防止极便宜、极快或接近完美的臂之间的微小差别被放大成巨大的比值。
- $(C^{\rm ref},T^{\rm ref},Q^{\rm ref})$ 是参照锚点。锚点的选取（I 档用参照臂的实测值，II 档在成本、时间和质量上各取一个有上下界限制的锚点，III 档不出 $V$）是第 10 步，还在计划中。在那之前，只有调用方传入锚点时 $V$ 才正确。

总体 $V_i$ 用同一个公式，代入总体值即可。单元级的 $V_{iu}$ 只用于诊断。 $V$ 在对数空间里计算，要求 $c_0,t_0,\epsilon>0$、 $C,T\ge0$、 $Q\in[0,1]$。

### 6. 资格门槛 $\mathcal E_d$

*规范 §5。已实现。在探针做好之前（第 13 步），真实性和日志完整性由调用方传入。*

一条臂要通过全部五道门槛，才能进入某一层的主比较，也就是集合 $\mathcal E_d$：

1. **完整样本。** 该臂在本层没有 $\mathrm{miss}$ 单元，也没有 $\mathrm{fail}$ 单元： $N_{i,d}^{\rm miss}=0$ 且 $N_{i,d}^{\rm fail}=0$。
2. **样本量。** $U_d$ 是本层正权重单元的个数：

$$
n^{\rm comp}_{i,d}=\sum_{u\in d^+}\bigl(n^1_{iu}+n^0_{iu}\bigr)\ge\max(30,\,3U_d).
$$

3. **取消率和完成率。** $N^{\rm sub}_{i,d}$ 是本层提交给该臂的任务数：

$$
\frac{n^C_{i,d}}{N^{\rm sub}_{i,d}}\le0.20,\qquad
\frac{n^1_{i,d}+n^0_{i,d}}{N^{\rm sub}_{i,d}}\ge0.50 .
$$

4. **真实性和日志完整性。** 真实性档 A、A−、B 通过，C 不通过；靠 B 档通过的臂会标上“真实性未定”。日志完整性检查必须通过。目前这两项结果都由调用方传入，所以这两道门槛可不可靠，完全取决于调用方给的输入。
5. **参照底座。** 在本层每个正权重单元里，参照臂的 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$ 都有定义（不是 $\mathrm{NA}$）。参照臂没有 $\mathrm{miss}$ 单元是必要条件，但不够，因为有样本的单元也可能最后算出 $\mathrm{NA}$。

结果会给出该臂是否合格、没通过的每一道门槛，以及“真实性未定”标记。

<details>
<summary>实现说明</summary>

- 两道比率门槛用整数比较： $5n^C\le N^{\rm sub}$ 和 $2n^{\rm comp}\ge N^{\rm sub}$，所以边界上没有舍入问题。 $N^{\rm sub}=0$ 时两道比率门槛都不通过，也不做除法。
- 五道门槛每次都全部检查，没通过的全部列出，按固定顺序、不重复；不会在第一道失败时就停下。
- $n^C$ 和 $N^{\rm sub}$ 只在有数据的正权重单元上累加， $\mathrm{miss}$ 单元计 0。所以在含 $\mathrm{miss}$ 单元的层里，失败列表可能同时列出某道比率门槛。不管怎样，这条臂都会因为完整样本门槛而不合格。
- 参照底座门槛从调用方接收参照臂的三元组，不检查它们是不是真的由参照臂算出。同一个单元传两次会返回错误。
- 归因时，每个失败标签都对回五道门槛中的一道；完整样本门槛已经没过时，主要失败原因里不再列两道比率门槛（第 9 步）。
- 第 9 步已经用规范里的例 6 对照过这些门槛。

</details>

### 7. 诊断表

*规范 §5。已实现为库函数；表格本身还没有展示出来。*

某一层里有 $\mathrm{miss}$ 或 $\mathrm{fail}$ 单元的臂不在 $\mathcal E_d$ 里。诊断表给这样的臂单独算一个带标注的估计，永远不和主结果混在一起。

**准入。** 臂至少要有一个 $\mathrm{valid}$ 单元，并且满足下式，才给诊断分：

$$
{\rm ESS}_{i,d}=n^{\rm comp}_{i,d}+\kappa_{\rm eff}\ge3 .
$$

这里的 $\kappa_{\rm eff}$ 是第 3 节的先验强度 $\kappa_{iu}$ 按 $\omega_u$ 在本层全部正权重单元上加权平均的结果。规范没有说 $\mathrm{miss}$ 单元怎么处理；决策记录把它按 $\kappa=0$ 计，权重仍算在分母里。用 Jeffreys 先验时 $\kappa=0$， $\mathrm{ESS}$ 就等于 $n^{\rm comp}$。

**填补空缺。** 填补值只用该臂本层 $\mathrm{valid}$ 单元的普通 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$，不用取消稳健版本。

- $\mathrm{miss}$ 单元有两个值。乐观值是各有效单元的加权中位数，成本、时间、质量分别取。取的是下中位数：先把有效单元的权重归一化，再把值排好序，累计权重第一个达到一半的那个值胜出。质量按缺陷 $1-Q$ 排序，所以平局时总是取更好的那个真实单元。保守值是每个维度上最差的有效值：最高的成本、最高的时间、最低的质量，三者可以来自不同单元。
- $\mathrm{fail}$ 单元只有一个值：每个维度上，取它的实测值和最差有效值中更差的那个。

填补后的单元按第 5 节在本层聚合两次：一次所有 $\mathrm{miss}$ 单元都取乐观值，一次都取保守值； $\mathrm{fail}$ 单元两次都用它唯一的那个值。有 $\mathrm{miss}$ 单元的臂以区间 $[V^{\rm diag,cons},V^{\rm diag,opt}]$ 展示；只有 $\mathrm{fail}$ 单元的臂得到单个 $V^{\rm diag}$，并标出不合格单元的总权重 $w^{\rm fail}_{i,d}$。 $V$ 用调用方传入的诊断参照来算；没有参照时，这一行没有 $V$。

**排序。** 各行按有效单元覆盖率从高到低排，相同时按模型名排：

$$
{\rm cov}_{i,d}:=1-w^{\rm miss}_{i,d}-w^{\rm fail}_{i,d}
$$

不提供按诊断 $V$ 排序的入口。

<details>
<summary>实现说明</summary>

- 诊断行里的层聚合值是填补以后算的。像规范例 8 里的 $A_C=0.165$ 这种原始实测层均值，要由调用方用实测值另算，库里不存。
- 臂没有准入时，结果里还不会写明是哪个条件没达到。
- 坏输入返回错误：同一个单元传了两次，权重或 $\kappa$ 不是有限数，或者 $\mathrm{fail}$ 单元缺完整的实测三元组。
- 已经和规范例题对照过：例 6 的 $F_{\rm thin}$ 单元和诊断聚合值 0.7875，例 7 的 $F_{\rm bad}$ 单元和 0.9000。例 8 的原始均值 0.1650 由第 6、7 步的测试对照。

</details>

### 8. 前沿

*规范 §6。已按层实现。总体推荐要等参照锚点分档（第 10 步），还在计划中。*

在某一层的合格臂里，如果臂 $j$ 在每个维度上都不比臂 $i$ 差（成本、时间不更高，质量不更低），并且至少有一个维度严格更好，就说 $j$ 支配 $i$。权重 $a$、 $b$、 $g$ 在这里不起作用。

$$
\mathcal F^{\rm off}_d=\{i\in\mathcal E_d:\nexists j\in\mathcal E_d,\ j\succ_{\rm off}i\},\qquad
\mathcal F^{\rm rob}_d=\{i\in\mathcal E_d:\nexists j\in\mathcal E_d,\ j\succ_{\rm rob}i\}
$$

$$
\mathcal F^{\rm rec}_d=\{i\in\mathcal F^{\rm off}_d:\nexists j\in\mathcal E_d,\ j\succ_{\rm rob}i\}
$$

$\succ_{\rm off}$ 比较普通的 $C^{\ast}$、 $T^{\ast}$、 $Q^{\ast}$， $\succ_{\rm rob}$ 比较取消稳健版本。 $\mathcal F^{\rm off}_d$ 是官方前沿， $\mathcal F^{\rm rob}_d$ 是取消稳健前沿， $\mathcal F^{\rm rec}_d$ 是推荐集：官方前沿上那些在取消稳健值上没有被任何臂胜过的臂。

<details>
<summary>实现说明</summary>

- 调用方传入 $\mathcal E_d$ 里的臂；前沿函数自己不检查资格。
- 普通三元组里有 $\mathrm{NA}$ 的臂不进 $\mathcal F^{\rm off}_d$；取消稳健三元组里有 $\mathrm{NA}$ 的臂不进 $\mathcal F^{\rm rob}_d$，也不参加任何取消稳健比较。
- 取消稳健值只在普通值为 $\mathrm{NA}$ 的地方才是 $\mathrm{NA}$，所以官方前沿上的臂一定有完整的取消稳健三元组，可以判断它能不能进 $\mathcal F^{\rm rec}_d$。反过来的情况规范没有写；库里会检查它不会出现，但只在调试构建里检查。
- 如果某条臂的取消账单只有下界，规范对它禁用取消稳健支配，并标上“账单过粗”。这样的臂不进 $\mathcal F^{\rm rob}_d$，也不参加任何取消稳健比较，既不支配别人，也不被别人支配。所以它如果在官方前沿上，就没有臂能在取消稳健值上胜过它，会留在 $\mathcal F^{\rm rec}_d$ 里，结果里也会把它列为账单过粗。这个标注的展示在计划中（第 10 步）。
- 另有一个辅助函数，返回 $V$ 并列最高的所有臂；测试检查了这些臂都在官方前沿上。
- 还没实现的： $\mathcal F^{\rm rec}_d$ 为空时把 $\mathcal F^{\rm rob}_d$ 列为“取消稳健备选”（不得标成官方第一），检查总体推荐至少在一个层的前沿上的内部校验，以及总体 $V$ 和它的条件，这些要等第 10 步。

</details>

## 使用

### 给用户

计划中。目前还没有可以安装或运行的应用。计划做成一个常驻系统托盘的桌面应用。

### 给开发者

核心库和存储库（不需要系统 GUI 库；内置 SQLite 需要 C 编译器）：

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

网页前端（Node.js 20 及以上）：

```sh
cd web
npm ci
npm run lint
npm run typecheck
npm run build
```

桌面外壳：`src-tauri/` 是单独的 Cargo 包，这样测试核心库时不需要 GUI 库。构建它需要 Tauri 2 的系统依赖（Linux 上是 WebKitGTK 4.1 及相关开发包）。先构建网页前端，再进入 `src-tauri/` 运行 `cargo build`。CI 会安装这些依赖，并对外壳运行 `cargo check` 和 `cargo clippy`。外壳目前只做过编译检查，还没有运行或打包过。

## 密钥和隐私

真实的 API key 只放在本地 `.env` 文件里，该文件已被 git 忽略。`.env.example` 只列变量名。agent-value 只保存一条路线所用环境变量的名字，从不保存它的值；数据库里没有存 key 值的列。

所有数据都在一个本地 SQLite 文件里。提示词和代码文本从不保存：只存类别、长度，以及一个 HMAC-SHA256 摘要，摘要的密钥放在数据库之外。任务级数据 180 天后清除，存储层可以导出全部数据，也可以删除全部数据。
